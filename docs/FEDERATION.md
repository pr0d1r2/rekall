# Federation

`rekall`'s spec is not one file. It is **22 of them** — a root, `src`, and one
per module — each owning the rules for its own directory.

## Why

The source tree is **134,589 tokens**. That overflows a 131,072 window on its
own, before any prose. Loading "the spec" to work anywhere meant loading the
law for nineteen modules you were not touching.

Federation is `rekall`'s own thesis turned on its own spec: a rule should
arrive where it applies rather than compete for window everywhere. `§G` argues
that about a corpus; this is the same argument about the document that argues
it.

## The shape

```
.                       the ROUTE: crate-wide law, and the §F edge
`-- src                 what every module inherits
    |-- apply           executing an extraction
    |-- catch           the second intake
    |-- check           the gate over extractions
    |-- classify        signals, weights, class x sharpness
    |-- cli             dispatch, arguments, exit codes
    |-- config          rekall.toml and its two scopes
    |-- corpus          reaching the files
    |-- hook            the harness adapter
    |-- init            the cold start
    |-- issue           handing an extraction to a registry
    |-- ledger          the store
    |-- log             reading the ledger back
    |-- plan            the extraction diff
    |-- recall          which skills load here
    |-- revert          reversing one extraction
    |-- runner          executing a rule under a CPU bound
    |-- scan            the inventory
    |-- show            one statement argued in full
    |-- statement       prose into statements
    |-- tokens          delegating every count to itok
    `-- trigger         the fenced block and its refusal clause
```

Generated by `sherd graph --tree`, from the `§F` tables, so it cannot drift
from what the specs declare.

## The root is a route, not a reading

The root holds two things: the crate-wide law every node inherits, and the
`§F` edge saying where the rest lives. It is read to **find** a node, not to
learn a rule.

That is why ~8k tokens is the right size for it and would be the wrong size
for a document anyone reads end to end. `.context-limits` caps it at 8,700,
and caps a node's **chain** — root plus `src` plus the node, which is what an
agent actually loads to work in one place — at 10,000. Largest today is
`src/catch` at 8,963.

## What a node owns, and what it does not

Every `§F` row carries both halves:

```
dir|owns|⊥owns|tokens
apply|EXECUTING an extraction: the artifact written, the source span
      deleted, the pointer left in its place|the DIFF that decided it
      (`plan`), the store's shape (`ledger`), and undoing it (`revert`)|-
```

The second column is not decoration. An edge naming only what a node owns
sends a reader looking in the wrong place for everything else.

## Where a rule lives

A rule goes to the node that owns it. A rule two nodes cite goes to their
**common ancestor** — putting it in one of them would hide it from the other.
A rule nobody claims stays at the root and is named there.

Placement is a judgement and stays one: `sherd adopt` moves nothing without a
map handed back to it.

## Citations

A citation crossing an edge is written in backticks and is a path:
`` `src:V43` ``, `` `src/revert:V9` ``, `` `.:R17` `` for the root. A bare id
is read against the spec it appears in, so an unquoted one resolves to the
wrong rule or to none.

**One friction worth knowing:** in `§V` prose, `mth` reads any `V<n>` as local
however it is qualified, while `sherd` resolves the qualified path. The two
disagree, and the `§T` cites column is the form both accept — so a
cross-edge citation belongs there rather than in prose.

### A qualified citation is not checked at all

`sherd validate` catches a bare local id that no `§V` declares — it refused
`V47` in `src/apply` while that rule lived in `src`. It does **not** resolve a
qualified one. `` `config:V25` `` passes cleanly, and `config` declares only
`V36`.

Measured by writing that exact citation into `src/cli/SPEC.md` and watching a
clean `sherd validate`. So the form the federation *requires* for crossing an
edge is the form nothing verifies, which is the worse half to leave unchecked.

Together with the orphan report above, that is the shape of the gap: **the
tooling reads one file at a time, and every cross-node claim is on trust.**
Closing it needs a checker that loads the whole tree and resolves both
directions — the same checker `T38` is blocked on.

## The tooling

`microlith` (`mth`) is intra-file by design and has **no `§F` verb at all**, so
an edge table it cannot read would be a declaration nothing checks — the thing
`§V22` forbids. The cross-file half is [`sherd`](https://github.com/pr0d1r2/sherd),
a pinned flake input:

| command | what it answers |
|---|---|
| `sherd validate` | the DAG, the ids, every chain against its ceiling, nav drift |
| `sherd sync --check` | whether a `§N` would be rewritten from its `§F` |
| `sherd budget` | what each node's chain costs |
| `sherd lens <dir>` | the context pack for one node |
| `sherd graph --tree` | the diagram above |
| `sherd split` | where the boundaries would fall, writes nothing |
| `sherd adopt` | migrate a single-file spec onto a federation, from a map |

`validate` and `sync --check` are gate steps, so the edges have a runner.

## Reading a node

`SPEC.md` files are caveman-encoded and the symbols are load-bearing:

```
∴ therefore   ∵ because   ∀ for all   ! must
⊥ not/never   & and       · separator
```

Sections run `§G` goal · `§F` federation · `§N` nav · `§C` constraints ·
`§I` interfaces · `§R` research · `§V` invariants · `§T` tasks · `§B` bugs.
`§R` and `§B` are where the evidence lives — `§B` in particular, because a
bug paired with the invariant that now catches it is worth more than the
invariant alone.

`§N` is **generated** from `§F` by `sherd sync`. Editing it by hand is the
drift, not the fix.

## What this is not

Federation here is not a claim that the spec is large. At 8,107 tokens the
root is small; it is *tightly capped*, which is a different thing. What
overflows is spec-plus-code, and the node is what makes that loadable.

Per-**verb** federation was costed and rejected: 11 nodes of residue to
relocate 11 rows, a 3.3x loss, and the rules that would have justified it
(`src:V41`, `src:V42`, `src:V43`) are precisely the ones spanning three verbs
each. The boundary that exists is the module, and `sherd split` proposed it
before anyone argued for it.

### `mth derive` cannot see across an edge

Run it on a single node and every uncited-here invariant is reported as an
orphan, because the citation lives in another file:

```console
$ mth derive src/revert/SPEC.md
orphan V9: declared, cited by nothing -- dead rule, or a missing citation?
```

`V9` is cited from three other nodes. All 23 nodes report at least one of
these, and every one checked was a false positive. `mth` owns the intra-file
format and knows nothing about `sherd`'s edges; that is the seam working as
designed, not a defect in either tool.

It matters for one reason: `mth derive`'s orphan report **cannot be gated
as-is**. A gate step that failed on 23 false orphans would be a step people
learn to bypass, which is worse than not having it. Federated orphan
detection needs a checker that reads the whole tree.
